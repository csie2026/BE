# 회원탈퇴 구현 — Issue #24 정책 후속 작업

## 동작과 삭제 범위

`DELETE /api/users/me`는 로그인 세션, CSRF 토큰, 본문의 `expectedUserId`와 정확한 `confirmation: "탈퇴"`를 요구한다. expectedUserId는 계정 전환 검증용이며 삭제 권한은 세션에 고정된 회원 ID에서 얻는다. 정상 응답은 캐시하지 않는 204이다.

트랜잭션에서 회원 행을 잠근 후 점수 변경 이력·일별 인증·활동 점수·공개 후기 보너스·등산일지·GPS 활동·이미지·월별 목표·회원 순으로 삭제한다. 실패하면 전체를 롤백한다. 다른 회원과 산·코스 공통 데이터는 보존하며 익명 사본을 만들지 않는다.

현재 업로드 저장소는 `member_personal_images.content` BYTEA이다. 이 행 삭제는 메타데이터뿐 아니라 실제 애플리케이션 이미지 본문도 삭제한다. 외부 파일 저장소나 새로운 삭제 시스템은 추가하지 않았다. DB 백업/WAL/로그 및 물리 매체 잔존까지 즉시 제거한다고 보장하지 않는다.

운영 DB 삭제가 커밋된 후 내부 OAuth authorized-client 캐시와 요청 세션/쿠키를 정리한다. 외부 Google/Kakao 계정 삭제 및 제공자 동의 철회는 호출하지 않는다. 같은 소셜 계정 재로그인은 새로운 회원 ID로 생성된다.

## 세션과 기존 기능의 충돌 처리

기존 principal이 provider/providerId만 보유하면 재가입 뒤 과거 세션이 새 회원을 조회할 수 있었다. 이제 로그인 당시 memberId를 principal에 고정하고 보호 API마다 DB의 해당 ID/provider 조합을 검증한다. 탈퇴한 ID는 다른 기기의 다음 API 요청도 거부하며 그 요청의 세션/쿠키를 폐기한다. 원격 세션 객체를 즉시 전부 열거·파괴하는 구현은 아니다. 운영 중인 모든 인스턴스에 동일 코드가 배포되어야 한다.

기존 ID 미포함 세션은 재로그인이 필요하다. DB 장애는 503으로 실패하고 탈퇴로 오인하거나 세션을 삭제하지 않는다. 일반 세션 만료, CSRF, 로그아웃 설정은 유지한다. OAuth authorized-client 이름도 회원 ID에 고정해 재가입 계정과 분리한다. 기존 회원 재로그인과 삭제는 동일 회원 행 잠금으로 조정한다.

기존 V1~V7 마이그레이션과 스키마는 변경하지 않았다. 활동·일지·목표·이미지 쓰기 경로의 기존 소유권/잠금 정책을 유지한다. 통합 테스트의 인증 fixture만 새 principal 형식으로 맞췄다.

## 검증 상태

- 추가: WithdrawalIntegrationTests 9개, ActiveMemberSessionFilterTests 5개.
- 범위: 실제 API로 만든 연결 데이터 삭제, 이미지 본문 제거, 타회원 보존, 모든 기존 세션 거절, 재가입, CSRF·인증·명시적 확인, 계정 전환, 동시 삭제, FK 오류 롤백, OAuth 캐시 분리, DB 장애.
- 이 작업 환경: Java 소스 96개 문법 검사 통과, V1~V7 기반 H2 SQL 검증 30개 통과.
- Spring/JPA/Security 통합 테스트는 Java 21 환경에서 실행 대기. 위 문법/SQL 검증은 Maven 빌드나 PostgreSQL 회귀 테스트 통과를 뜻하지 않는다.

## 추가 정책/출시 검토

일반 개인정보는 운영 DB에서 삭제한다. 로그·백업 보존 기간, 법령상 별도 보존 대상/서비스 분류, 개인정보 처리방침 및 약관 동의, 제공자 동의 철회 범위는 별도 결정이 필요하며 구현에서 임의 기간을 정하지 않았다. GPS 서비스의 위치정보 관련 의무 적용 여부도 담당자의 검토가 필요하다. 해당 검토 이전에 법정 보존까지 충족했다고 선언하지 않는다.
